## 一、概念层:3 分钟理解业务

### 1.1 核心术语

| 术语 | 定义 | 同义词/备注 |
|------|------|-------------|
| **心理测评** | 通过标准化工具测量个体心理特质(能力、性格、动机等)的科学方法 | 心理测量、人才测评、assessments |
| **受测者** | 参与测评的个体,通常是企业员工或候选人 | 被试、测评对象 |
| **客户** | 购买测评服务的企业或组织 | 甲方、委托方 |
| **常模** | 特定人群在测评工具上的得分分布,用于解释个体得分的参照标准 | Norm、参照群体 |
| **信度/效度** | 测评结果的一致性与准确性 | Reliability / Validity |
| **白标** | 将测评平台定制为客户品牌外观的服务模式 | White-label |
| **项目制交付** | 按单次项目提供测评服务,通常包含咨询和解读 | 定制服务 |
| **四顶帽子** | 独立个体在销售/顾问/交付/经营四种角色间切换的工作模型 | 见经营手册 §二 |
| **危机转介** | 受测者出现自伤/自杀类信号时,由经营者书面通报客户 EAP/HR,自身不承担临床干预 | 见经营手册 §五 |


### 1.3 核心假设

1. **科学性假设**:使用的测评工具均经过信效度验证,有可靠的常模数据
2. **合规性假设**:数据处理符合《个人信息保护法》和 GDPR(如适用)
3. **客户有效性假设**:客户提供的受测者信息(姓名、邮箱、部门)准确无误
4. **技术稳定性假设**:测评平台可用性 ≥99.5%,支持中等规模并发(独立个体阶段不追求 99.9%)
5. **独立个体假设**:同时进行项目数 ≤3,年度 12–15 个项目(见经营手册 §6.1)

**正常流转**:线索 → 准入 → 需求 → 签约 → 执行 → 报告 → 收尾 → 完成
**异常终止**:淘汰、流失、取消(进入复盘日志,见经营手册 §3.4)
**循环路径**:续约 → 需求确认(新一轮)
**并行旁路**:任意阶段触发危机信号 → 立刻戴 🧠 顾问帽,启动危机干预协议(经营手册 §5.3)

### 2.3 决策分叉点(以阈值替代审批)

| 决策点 | 位置 | 判断条件 | 分支 A | 分支 B | 阈值依据 |
|--------|------|----------|-------|-------|---------|
| **准入决策** | 阶段0结束 | 准入评分 | ≥50:进入阶段1 | <50:淘汰 | 经营手册 §3.2 |
| **风险应对** | 阶段0结束 | 评分 50–69 | 制定降级方案后进入 | 拒绝或拆小试单 | 经营手册 §3.2 报价折扣 + §6.4 定价底线 |
| **方案确认** | 阶段1结束 | 客户是否签字 | 签字:进入阶段2 | 不签字:补充访谈 | — |
| **合同金额阈值** | 阶段2 | 合同金额 | ≤5万模板直签 / 5–20万自检清单 / >20万外部律师审 | < 单价底线则拒 | 经营手册 §3.2 + §4.3 |
| **项目周期阈值** | 阶段2 | 周期 | ≤8周直接接 / >8周拆里程碑 | 与现有 ≥3 个并行项目冲突则延期 | 经营手册 §3.2 + §6.1 |
| **单客户额度** | 阶段2 | 单客户年度占比 | <30% 直接接 / 30–50% 启动多元化预警 | >50% 不接或要求 60%+ 预付 | 经营手册 §3.2 |
| **项目启动** | 阶段3开始 | 50% 预付款是否到账 | 到账:启动 | 未到账:不开测评链接 | 经营手册 §6.2 |
| **质量检查** | 阶段3执行中 | 完成率 | 50%/80%/100% 三档自检 | 未达标:补测/范围调整 | 质量检查清单 |
| **报告交付** | 阶段4结束 | 报告自检清单 | 全打勾:交付 | 未全打勾:不允许进入下一状态 | 经营手册 §3.3 |
| **范围变更** | 阶段3/4 | 工作量增加 | <10% 口头确认 / 10–30% 书面变更不加价延期 / >30% 变更+加价+延期 | — | 经营手册 §3.2 |
| **危机信号** | 任意阶段 | 受测者自伤/自杀类信号 | 立刻启动危机干预协议 | — | 经营手册 §5.3(P1事件) |
| **应收红线** | 阶段3-5 | 单客户应收账款 | >月度成本×3:暂停新工作 / >¥10万 且 >30天:启动律师函评估 | — | 经营手册 §6.2 |
| **续约决策** | 阶段5结束 | 客户意向 + 容量 | 有意愿且容量未满:续约 | 容量已满:延期 / 推荐合作伙伴 | 经营手册 §6.1 |

### 🔍 阶段 0:客户准入与商机评估

| 属性 | 内容 |
|------|------|
| **目标** | 筛选合格客户,评估商机质量,决定是否投入资源 |
| **周期** | 1–2 个工作日 |
| **主帽子** | 🎩 销售帽 |
| **输入** | 客户线索(官网/活动/转介绍) |
| **输出** | 《客户准入评分卡》《商机记录》 |
| **AI 替代** | 客户背调(LLM 检索 + 工商信息汇总);评分卡自动算分 |
| **外包触发** | 跨境/合规风险高客户 → 一次性律师审(经营手册 §4.3) |

**关键步骤**(4 步,共 60–80 分钟):
1. **信息初登**(15min):记录客户基本信息、来源、联系人
2. **准入评估**(30min):8 维度评分(企业规模/行业匹配/预算/决策周期/数据安全/历史合作/竞争态势/战略价值),总分 100 分
3. **商机分级**(15min):绿灯(≥70)/黄灯(50–69)/红灯(<50)
4. **阈值决策**(15min):绿灯进 / 黄灯需风险应对 / 红灯淘汰

**自检门禁**:
- ✅ 评分卡 8 维度全部打分
- ✅ 商机分级与处置方案写入项目档案
- ✅ 红灯淘汰原因记录(用于月度复盘)

**异常路径**:
- 红灯 → 写入复盘日志 → 月底分析淘汰原因分布
- 黄灯 → 制定降级方案(小额试单/缩范围/提高预付比) → 进入阶段 1

**详细文档**:[stage-0-客户准入.md](SOP/stage-0-客户准入.md)

### 🎯 阶段 1:需求确认与方案设计

| 属性 | 内容 |
|------|------|
| **目标** | 深入理解客户需求,设计匹配方案,获得客户书面确认 |
| **周期** | 3–5 个工作日 |
| **主帽子** | 🧠 顾问帽 |
| **输入** | 阶段 0 通过的客户 + 准入评分卡 |
| **输出** | 《需求确认书》《测评方案》《项目里程碑计划》 |
| **AI 替代** | 访谈提纲生成;录音转写 + 会议纪要摘要;方案模板填充 |
| **外包触发** | 客户要求面对面解读 ≥50 人 → 持证心理咨询师(经营手册 §4.3) |

**关键步骤**(3 步,共 3–5 天):
1. **需求调研**(1–2 天):业务需求访谈(8 类核心问题)+ 技术需求(集成/接口/数据流)
2. **方案设计**(1–2 天):测评工具匹配 → 报告颗粒度评估 → 项目计划与里程碑
3. **方案确认**(0.5 天):客户演示 → 书面/电子签字确认

**自检门禁**:
- ✅ 方案与客户需求匹配度自评 ≥90%
- ✅ 客户书面/电子签字确认
- ✅ 里程碑日期与「同时进行项目 ≤3」无冲突

**异常路径**:
- 需求不清晰 → 补充访谈(超过 2 轮仍不清晰则判定淘汰)
- 客户不认可方案 → 调整(≤2 次)或流失

**详细文档**:[stage-1-需求确认.md](SOP/stage-1-需求确认.md)

### 📝 阶段 2:合同签约与合规自检

| 属性 | 内容 |
|------|------|
| **目标** | 完成商务谈判,签署合同,确保合规与现金流安全 |
| **周期** | 3–7 个工作日 |
| **主帽子** | 🎩 销售帽 + 📊 经营帽 |
| **输入** | 签字确认的《需求确认书》《测评方案》 |
| **输出** | 《合同正本》《合规自检报告》《项目档案》 + 50% 预付款 |
| **AI 替代** | 合同模板填充(变量替换);标准价目表 + 折扣阈值校验 |
| **外包触发** | 合同金额 >20 万 / 客户提非标条款 / 跨境数据 → 外部律师(经营手册 §4.3) |

**关键步骤**(3 步,共 3–7 天):
1. **报价谈判**(1–2 天):成本核算 → 阈值化报价(经营手册 §3.2 折扣阈值)→ 24h 冷静期(若超阈值)
2. **合同起草与自检**(1–3 天):模板选型 → 条款定制 → 合同自检清单(经营手册 §3.3)逐项打勾
3. **签署与首付款**(1–2 天):电子签 → 发送付款通知 → 50% 预付款到账确认

**自检门禁**(经营手册 §3.3 合同清单):
- ✅ 付款条款三项合计 = 100%（默认 50/30/20，可按合同调整，系统强制校验）
- ✅ 测评工具来源与授权写明
- ✅ 数据保留期与销毁时点写明
- ✅ 危机干预转介义务写明
- ✅ 单方退出/暂停条款写明
- ✅ 自己读完一遍无看不懂的条款
- ✅ 50% 预付款到账（未到账不进入阶段 3）

**异常路径**:
- 价格谈判破裂 → 让步阈值(标准价 70%)以下拒绝或拆小试单
- 客户提非标条款 → 律师审(支付一次性费用)→ 加价覆盖成本
- 预付款 14 天未到账 → 暂停项目 + 重新报价或终止

**详细文档**:[stage-2-合同签约.md](SOP/stage-2-合同签约.md)

### ⚙️ 阶段 3:项目执行与交付监控

| 属性 | 内容 |
|------|------|
| **目标** | 按计划完成测评执行,确保数据质量与进度 |
| **周期** | 2–6 周(按项目规模) |
| **主帽子** | 🛠 交付帽(关闭即时通讯,深度工作日为主) |
| **输入** | 合同 + 50% 预付款到账 |
| **输出** | 《项目执行日志》《进度报告》《质量检查记录》《危机信号台账》 |
| **AI 替代** | 邀请邮件合并发送;Cron 自动催测;进度看板自动汇总;FAQ 机器人 |
| **外包触发** | 平台技术超出可维护复杂度 → 前端外包按周计费(经营手册 §4.3) |

**关键步骤**(4 步):
1. **批次配置与样本导入**(1–2 天):创建测评批次（填写项目负责人 + 危机应急联系人，均 NOT NULL）→ CSV 导入匿名样本 ID（无 PII）
2. **项目启动会**(0.5 天):按经营手册 §7.2 的「三句话」期望管理;明确我是唯一对接人
3. **环境配置与试跑**(1–2 天):租户开通 → 白标配置 → 我自己完整跑一遍测评流程
4. **执行与监控**(2–6 周):线下测评执行（主路径：本地软件 → 导出结果 → 上传平台）→ 进度看板 → 异常处理 → 30% 中期款催收
5. **三档自检**(完成率每达一档触发):50% 样本充足性 / 80% 进度预警 / 100% 数据质量

**自检门禁**(经营手册 §3.3 上线清单):
- ✅ **批次已创建**：项目负责人与危机应急联系人均已填写（NOT NULL）
- ✅ **样本 ID 已全部导入**：数量与合同约定一致，无 PII 字段
- ✅ 测试链接自己完整跑一遍
- ✅ 数据落库且字段完整
- ✅ 链接过期时间正确
- ✅ 客户白标 logo/文案确认
- ✅ 受测者 FAQ ≥5 个
- ✅ 危机干预联系方式在测评首页可见
- ✅ 50% 样本量达到工具最低要求

**异常路径**:
- 进度滞后 → 资源追加(我加班 / 砍范围)
- 数据质量问题 → 补测或退还相应款项
- 客户范围变更 → 阈值化处理(经营手册 §3.2)
- 危机信号 → 立刻切顾问帽,启动 §5.3 协议

### 📊 阶段 4:报告出具与洞察交付

| 属性 | 内容 |
|------|------|
| **目标** | 生成高质量报告,交付洞察,协助客户应用 |
| **周期** | 5–7 个工作日(数据收集完成后) |
| **主帽子** | 🧠 顾问帽 + 🛠 交付帽 |
| **输入** | 完成的测评数据 |
| **输出** | 个人报告 + 群体报告 + 《报告交付确认单》+ B端门户访问 Token |
| **AI 替代** | 报告模板 + LLM 段落填充 + 规则引擎;群体统计 Python/SQL 脚本 + 可视化模板;PPT 大纲生成 |
| **外包触发** | 群体报告对外汇报 → 设计师做精排 PPT(经营手册 §4.3) |

**关键步骤**(4 步):
1. **结果上传与样本关联**(0.5 天，主路径专属):从本地测评软件导出结果文件 → 在工作台上传 → 系统自动匹配 sample_id → 样本状态更新为 `completed`
2. **数据分析**(1–2 天):清洗 → 统计 → 洞察提取
3. **报告生成**(1–2 天):个人报告（模板+LLM，**初期 100% 人工复核**）→ 上传平台关联 sample_id → 顾问审核发布；群体报告（模板+脚本）
4. **报告自检**(0.5 天):报告自检清单逐项打勾
5. **生成B端门户Token**(0.5 天):审核通过后生成专属访问 Token → 通知B端通过门户（`/portal/batch/[token]`）查看进度与下载报告
6. **交付与解读**(1–2 天):B端下载报告 + 解读会（线下 ¥3k–8k/场或线上）

**自检门禁**(经营手册 §3.3 报告清单):
- ✅ **结果文件已上传**：所有样本状态更新为 `completed`
- ✅ 数据样本量 ≥ 工具最低要求
- ✅ 个人报告每个受测者都有，不缺漏；已上传关联 sample_id
- ✅ **个人报告经顾问审核**，状态为 `published`（禁止 AI 直接对客）
- ✅ 群体报告口径与原始数据可追溯(留 SQL/脚本)
- ✅ **未使用临床诊断词汇**(无「抑郁症」「焦虑障碍」等)
- ✅ 高风险个体已识别，转介建议已写明
- ✅ PDF 本机预览 + 手机预览各一次，无乱码错别字
- ✅ 客户敏感信息脱敏粒度符合合同约定
- ✅ **B端门户 Token 已生成**，访问链接已通知B端项目负责人

**红线**(经营手册 §4.2):
- ❌ 任何写有受测者姓名的报告内容禁止 AI 直接对客
- ❌ 报告中禁止使用临床诊断词汇

**异常路径**:
- 客户不认可结果 → 解释原理 + 提供常模 → 必要时复测(成本评估后决定)
- 敏感信息泄露 → 立刻启动应急(致歉 + 召回 + 销毁记录 + 复盘)

## 四、治理层:自我治理与持续改进

> 独立个体没有 PMO/管理层。治理 = **每月戴一次 📊 经营帽,30 分钟,看 5 个数字 + 写复盘**(经营手册 §3.4)。

### 4.1 经营度量指标(月度)

| 类别 | 指标 | 计算 | 健康阈值 | 红线 |
|------|------|------|---------|------|
| **容量** | 同时进行中项目数 | 当前在执行+报告阶段的项目 | ≤3 | >3 持续 2 个月 → 触发扩张评估(经营手册 §九) |
| | 帽子时间占比偏差 | 实际占比 vs 25/30/30/15 | 任一偏差 ≤10pt | 任一偏差 >20pt 持续 2 个月 |
| **现金流** | 应收账款 / 月度成本 | 期末应收 / 月固定支出 | ≤2 | >3 |
| | 应急缓冲月数 | 现金 / 月固定支出 | ≥3 个月 | <2 个月 |
| | 单客户营收占比 | 单客户年度回款 / 总回款 | ≤30% | >50% |
| **质量** | 报告自检一次通过率 | 不需返工的报告比例 | ≥85% | <70% |
| | NPS | 推荐者% − 贬损者% | ≥40 | <0 |
| | 阈值触发后悔率 | 复盘判断「决策错误」的阈值事件占比 | ≤10% | >30% |
| **增长** | 续约率 | 续约客户数 / 到期客户数 | ≥60% | <40% |
| | 转介绍线索占比 | 转介绍线索 / 总线索 | ≥40% | <20% |

### 4.2 月度复盘(替代 PDCA)

每月 1 日(或最近工作日)戴 📊 经营帽,30 分钟,回答经营手册 §3.4 的 5 个问题:

1. 上月触发了哪些阈值?事后看决策对不对?
2. 上月有哪些自检清单**没打勾就过去了**?为什么?
3. 上月的异常事件(P0/P1/P2/P3 分类)?
4. 上月四顶帽子时间占比 vs 目标(25/30/30/15)?
5. 下月需要调整的 1 件事是什么?

**输出**:`docs/复盘日志/YYYY-MM.md`(单文件,Markdown,≤1 屏)。

### 4.3 季度/年度评估

| 节奏 | 时长 | 关注点 |
|------|------|--------|
| 月度 | 30 min | 阈值/自检/异常/容量 → 复盘日志 |
| 季度 | 半天 | 度量指标趋势 + 客户结构 + 现金流 + 红线指标 → 调整定价/容量/外包 |
| 年度 | 1 天 | 战略级:是否仍是「独立个体」阶段 / 触发经营手册 §九扩张评估 |

### 4.4 文档变更管理

| 变更类型 | 流程 | 文档动作 |
|----------|------|---------|
| 措辞优化 | 直接改 | 不需版本变更 |
| 步骤调整 | 改 + 复盘日志说明原因 | 小版本号 +1(v1.x.y → v1.x.y+1) |
| 阶段/RACI 级变更 | 月度复盘窗口决定 + 24h 冷静期 | 中版本号 +1(v1.x → v1.x+1) |
| 宪法级冲突 | 修改经营手册 + 同步全部下游文档 | 大版本号 +1 + 复盘记录 |
