## 1. 产品概述与愿景

### 1.1 产品定位

**心理测评全流程管理SaaS平台** —— 面向企业客户（B2B）的心理测评服务交付系统，覆盖从客户准入到项目收尾的完整业务生命周期。

### 1.2 产品愿景

> 成为企业心理测评服务领域最高效、最可靠、最智能的项目交付平台，让每一次测评服务都成为客户信任的基石。

### 1.3 核心目标

| 维度 | 目标 | 度量指标 |
|------|------|----------|
| **效率** | 缩短项目交付周期 | 平均交付周期 ≤ 14 天 |
| **质量** | 降低交付缺陷率 | 客户投诉率 ≤ 2% |
| **增长** | 提升客户续约率 | 年度续约率 ≥ 75% |
| **智能** | 自动化重复工作 | 人工操作减少 60% |

### 1.4 业务边界

```
┌─────────────────────────────────────────────────────────┐
│                    平台覆盖范围                           │
├─────────────────────────────────────────────────────────┤
│  ✅ 客户准入评估    ✅ 需求调研管理    ✅ 合同流程        │
│  ✅ 项目执行跟踪    ✅ 报告生成交付    ✅ 收尾与续约      │
│  ✅ 数据安全合规    ✅ 质量检查控制    ✅ 异常处理        │
├─────────────────────────────────────────────────────────┤
│  ❌ 心理测评量表设计（外部专业工具）                       │
│  ❌ 临床诊断服务（需人工专家介入）                         │
│  ❌ 支付收款系统（集成第三方支付）                         │
└─────────────────────────────────────────────────────────┘
```

## 2. 目标用户与价值主张

### 2.1 用户画像

#### 主要用户：企业HR/组织发展负责人

- **痛点**: 心理测评项目分散管理、进度不透明、报告质量参差不齐
- **需求**: 一站式项目管理、实时进度追踪、标准化报告输出
- **使用场景**: 季度员工测评、招聘测评、团队建设分析

#### 次要用户：项目经理（内部）

- **痛点**: 多项目并行管理困难、客户沟通成本高、交付标准不统一
- **需求**: 项目看板、自动化提醒、模板化交付
- **使用场景**: 同时管理5-10个客户项目

### 2.2 价值主张

**对客户**: 透明、高效、专业的心理测评服务交付体验  
**对内部团队**: 标准化、可追踪、可度量的项目管理能力  
**对管理层**: 全局可视的业务运营数据与决策支持

                   └──────┬───────┘
                          │ 执行完成
                          ▼
                   ┌──────────────┐
         ┌────────│   报告交付    │◄────────┐
         │        └──────┬───────┘         │
         │ 报告修订       │ 客户确认        │

#### 4.1.2 状态转换规则

| 当前状态 | 可转换至 | 触发条件 | 自动动作 |
|----------|----------|----------|----------|
| 潜在客户 | 需求确认 | 准入评分 ≥ 70分 | 创建项目档案 |
| 需求确认 | 合同签约 | 需求文档签署 | 生成合同草稿 |
| 需求确认 | 潜在客户 | 需求变更重大 | 回退并记录 |
| 合同签约 | 项目执行 | 合同双方签署 | 创建执行计划 |
| 合同签约 | 需求确认 | 合同谈判失败 | 回退并记录 |
| 项目执行 | 报告交付 | 测试数据收集完成 | 触发报告生成 |
| 项目执行 | 合同签约 | 客户要求变更 | 变更审批流程 |
| 报告交付 | 项目收尾 | 客户确认报告 | 触发结项流程 |
| 报告交付 | 项目执行 | 报告需重大修订 | 回退并记录 |
| 项目收尾 | 已完成 | 结项审批通过 | 归档并更新CRM |

#### 4.1.3 审批工作流引擎

```yaml
审批流程定义:
  合同审批:
    - 步骤1: 项目经理提交
    - 步骤2: 法务审核 (金额 > 10万)
    - 步骤3: 财务审核 (金额 > 5万)
    - 步骤4: 总监审批 (金额 > 20万)
    - 步骤5: 客户签署
    
  报告发布审批:
    - 步骤1: 测评专家审核
    - 步骤2: 项目经理确认
    - 步骤3: 客户确认 (可选)
    
  结项审批:
    - 步骤1: 项目经理提交结项报告
    - 步骤2: 财务确认收款
    - 步骤3: 业务管理员归档
```

### 4.7 匿名批次测评交付模块

> **设计原则**：平台仅存储匿名样本ID（如S001、S002…），受测者PII由B端采购方自持ID↔真名映射，平台零PII存储。

#### 4.7.1 模块概述

匿名批次测评交付模块覆盖从合同签约到项目收尾的完整交付闭环，涉及三方角色：

| 角色 | 职责 |
|------|------|
| **平台方（经营者）** | 创建批次、配置联系人、导入样本ID、监控进度、出具报告、生成门户Token |
| **B端采购方** | 签合同付款、提供样本ID名单、通知受测者、通过门户查看/下载报告 |
| **C端受测者** | 完成测评（匿名，仅知自身ID）；可选经B端转发获取个人报告 |

#### 4.7.2 六阶段交付流程

```
① 合同签约 → ② 批次配置与导入 → ③ 测评执行 → ④ 报告出具 → ⑤ 客户访问 → ⑥ 项目收尾
```

#### 4.7.3 批次配置功能

**创建批次（平台方操作）**：

| 配置项 | 说明 | 约束 |
|--------|------|------|
| 批次名称 | 如"2026Q2领导力测评" | 必填 |
| 关联项目 | 绑定至已有项目 | 必填 |
| 项目负责人姓名 | B端日常对接联系人 | **必填 NOT NULL** |
| 项目负责人电话 | | **必填 NOT NULL** |
| 项目负责人邮箱 | | **必填 NOT NULL** |
| 危机应急联系人姓名 | 心理风险应急通知 | **必填 NOT NULL** |
| 危机应急联系人电话 | | **必填 NOT NULL** |
| 测评工具 | 使用的量表/测评软件 | 必填 |
| 预计样本数 | 计划参与人数 | 必填 |
| 截止日期 | 测评完成截止时间 | 必填 |

**样本ID导入（CSV格式）**：

```csv
sample_id,group_label,notes
S001,部门A,
S002,部门A,
S003,部门B,
```

- `sample_id`：唯一匿名标识，由B端生成（如S001~S999）
- `group_label`：可选分组标签（用于群体报告维度分析）
- `notes`：可选备注（不含PII）
- 平台校验：ID唯一性、格式合规、无PII字段

#### 4.7.4 付款条款灵活配置

**两层设计**：

```
系统级默认值（全局配置）
  ├── 预付款比例：50%（合同签约时）
  ├── 中期款比例：30%（报告交付后）
  └── 尾款比例：20%（项目收尾确认后）

合同级覆盖（每份合同可单独设置）
  ├── 可手工调整三项比例
  └── 校验规则：三项合计必须 = 100%（系统强制验证）
```

**付款条款JSON结构**：

```json
{
  "payment_terms": {
    "deposit_pct": 50,
    "midterm_pct": 30,
    "final_pct": 20,
    "custom_override": false,
    "milestones": [
      { "name": "预付款", "pct": 50, "trigger": "contract_signed" },
      { "name": "中期款", "pct": 30, "trigger": "report_delivered" },
      { "name": "尾款",   "pct": 20, "trigger": "project_closed" }
    ]
  }
}
```

#### 4.7.5 双路径测评执行

| 路径 | 说明 | 当前状态 |
|------|------|----------|
| **主路径（线下）** | 本地安装测评软件 → 受测者完成测评 → 平台方手动导出结果 → 上传至平台 → 关联样本ID | **当前使用** |
| **副路径（线上·未来）** | 微信小程序/H5页面测评 → 结果自动回传平台 → 实时更新样本状态 | 规划中，待测评软件提供API |

**主路径操作步骤**：
1. 平台方在本地测评软件中创建对应测评项目
2. B端将测评链接/说明转发给C端受测者
3. C端受测者在本地软件完成测评（匿名，仅填写样本ID）
4. 测评结束后，平台方从本地软件导出结果文件（CSV/Excel）
5. 平台方在工作台上传结果文件，系统自动关联样本ID
6. 系统更新对应样本状态为`completed`

#### 4.7.6 报告出具

**个人报告**：
- 平台方从本地软件导出单份PDF报告
- 在工作台上传并关联对应样本ID（如S001.pdf → S001）
- 顾问审核后标记为已发布

**群体报告**：
- 平台方基于全量样本数据生成
- 包含：总体分布、维度分析、分组对比（按group_label）、风险预警
- 生成结项报告（项目执行全程摘要）

**报告审核红线**：报告禁止AI直接对客交付，必须经顾问人工审核后方可发布。

#### 4.7.7 客户门户访问

**Token生成**：
- 报告发布后，平台方生成B端专属访问Token
- 门户入口：`/portal/batch/[token]`
- Token有效期：可配置（默认30天）
- 权限：查看批次进度、下载已发布报告

**B端门户功能**：

| 功能 | 说明 |
|------|------|
| 批次进度看板 | 样本完成率、各状态数量统计 |
| 个人报告下载 | 按样本ID下载对应PDF |
| 群体报告下载 | 下载完整群体分析报告 |
| 结项报告下载 | 下载项目交付结项摘要 |

**C端报告获取（可选）**：B端下载个人报告后，可自行通过ID↔真名映射转发给对应受测者，平台不直接接触C端。

#### 4.7.8 核心红线

| 红线 | 守护方式 |
|------|----------|
| 报告禁止AI直接对客 | 发布前必须经顾问审核，系统设审核状态卡口 |
| 项目负责人必填 | `projectContact*` 字段 NOT NULL 数据库约束 |
| 危机联系人必填 | `crisisContact*` 字段 NOT NULL 数据库约束 |
| 平台零PII存储 | 系统只存样本ID，禁止录入姓名/身份证/手机等PII |
| 单客户营收 ≤ 30% | Dashboard人工预警 |

## 6. 非功能需求

### 6.1 性能需求

| 指标 | 目标值 | 测试场景 |
|------|--------|----------|
| 页面加载 | ≤ 2秒 | 项目看板首页 |
| API响应 | ≤ 500ms | 项目列表查询 |
| 报告生成 | ≤ 30秒 | 100人群体报告 |
| 并发用户 | ≥ 100 | 同时在线操作 |
| 数据导出 | ≤ 60秒 | 1000条记录Excel |

### 6.2 可用性需求

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 系统可用性 | 99.9% | 年度停机时间 < 8.76小时 |
| 故障恢复 | ≤ 30分钟 | RTO (恢复时间目标) |
| 数据丢失 | ≤ 5分钟 | RPO (恢复点目标) |
| 备份频率 | 每日 | 全量备份 + 实时增量 |

### 6.3 安全需求

| 需求 | 实现方式 |
|------|----------|
| 传输加密 | HTTPS/TLS 1.3 |
| 存储加密 | AES-256-GCM |
| 密码策略 | 最小8位，含大小写+数字+特殊字符 |
| 登录安全 | 失败5次锁定15分钟，支持2FA |
| 会话管理 | JWT Token，有效期8小时 |
| 审计日志 | 全操作记录，保留180天 |
| 数据脱敏 | 敏感字段展示脱敏 |

### 6.4 兼容性需求

| 平台 | 支持版本 |
|------|----------|
| 浏览器 | Chrome 90+, Firefox 88+, Safari 14+, Edge 90+ |
| 移动端 | iOS 14+, Android 10+ |
| 分辨率 | 1920×1080 (推荐), 1366×768 (最低) |

### 6.5 可扩展性需求

- **水平扩展**: 支持多实例部署，负载均衡
