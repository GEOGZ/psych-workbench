# 阶段4：报告出具与洞察交付

> [← 返回全景SOP](../00-全景SOP.md)
>
> **阶段目标**：基于测评数据生成个人报告与群体报告，交付洞察并协助客户应用
> **平均周期**：测评结束后 3-7 个工作日
> **责任主体**：测评顾问主导，数据分析师支持，PM 协调交付

---

## 1. 触发条件

- 阶段 3 完成，数据收集结束且质量合格
- CRM 商机状态为「执行完成」

---

## 2. 操作流程

### Step 0：结果文件上传与样本关联（主路径专属，0.5 天）

> 线下测评（主路径）完成后，平台方手动上传测评结果并关联样本ID。

**执行人**：平台方（经营者）

#### 0.1 导出测评结果

从本地测评软件导出全批次结果文件（CSV 或 Excel 格式）：
- [ ] 文件包含所有样本ID对应记录
- [ ] 数据完整，无缺失行
- [ ] 文件编码 UTF-8

#### 0.2 上传至平台并关联样本

在工作台「测评批次 → 结果上传」：

1. 选择对应批次
2. 上传结果文件
3. 系统自动匹配 `sample_id` 字段，关联对应样本记录
4. 系统将匹配成功的样本状态更新为 `completed`
5. 确认匹配结果，检查未匹配数量是否为零

| 异常情况 | 处理方式 |
|----------|----------|
| 未匹配样本 | 检查sample_id拼写是否与导入时一致 |
| 重复上传 | 系统提示覆盖确认，确认后覆盖旧结果 |

**输出物**：全部样本状态更新为 `completed`，上传记录存档

---

### Step 1：数据分析（1-2 天）

**执行人**：数据分析师 + 测评顾问

#### 1.1 数据清洗

**操作内容**：
1. 导入原始数据到分析环境
2. 执行数据质量检查（参考 SOP-3 Step 4）
3. 处理缺失值（删除/插补/标记）
4. 标准化处理（如不同量表分数统一）

#### 1.2 统计分析

**分析维度**：

| 分析类型 | 方法 | 输出 |
|----------|------|------|
| **描述统计** | 均值、标准差、分布 | 各维度得分概况 |
| **差异检验** | t 检验、方差分析 | 群体间差异（部门/层级/性别） |
| **相关分析** | Pearson/Spearman | 维度间关联 |
| **聚类分析** | K-means / 层次聚类 | 人群细分画像 |
| **岗位匹配** | 自定义算法 | 人岗匹配度评分 |

#### 1.3 洞察提取

**关键洞察类型**：

1. **团队优势**：得分显著高于常模的维度
2. **团队短板**：得分显著低于常模的维度
3. **风险预警**：极端得分、内部冲突指标
4. **发展建议**：基于数据的 actionable insights

**输出物**：《数据分析报告》（内部使用）

---

### Step 2：个人报告生成（1-2 天）

**执行人**：测评顾问 + 技术团队（自动化生成）

#### 2.1 报告结构

```
个人测评报告

一、报告概览
   1.1 测评者基本信息
   1.2 测评工具与日期
   1.3 结果总览（雷达图/总分）

二、维度解读
   2.1 [维度A]：得分 + 解读 + 发展建议
   2.2 [维度B]：得分 + 解读 + 发展建议
   ...

三、综合洞察
   3.1 个人优势
   3.2 关注领域
   3.3 发展建议（短期/中期/长期）

四、应用场景
   4.1 岗位匹配度（如适用）
   4.2 团队协作建议（如适用）
   4.3 职业发展建议（如适用）

五、附录
   5.1 测评说明
   5.2 常模参照
   5.3 保密声明
```

#### 2.2 报告生成方式

| 方式 | 适用场景 | 优缺点 |
|------|----------|--------|
| **全自动生成** | 标准化测评，大批量 | 效率高，个性化有限 |
| **半自动生成** | 需要顾问微调 | 平衡效率与质量 |
| **全人工撰写** | 高管测评，定制化 | 质量最高，成本高 |

#### 2.3 质量控制

- [ ] 报告模板与方案一致
- [ ] 数据引用准确（与原始数据核对）
- [ ] 解读话术专业且易懂
- [ ] 无错别字、格式统一
- [ ] 敏感表述已审核（避免歧视性语言）

**输出物**：个人报告（PDF/在线链接）

---

### Step 2.5：个人报告上传与关联

> 主路径专属：从本地软件导出单份PDF，在工作台上传并关联样本ID。

**执行人**：平台方（经营者）

**操作步骤**：

1. 从本地测评软件导出各样本个人报告PDF
2. 在工作台「测评批次 → 报告上传 → 个人报告」中：
   - 选择对应批次和sample_id
   - 上传对应PDF文件
   - 系统自动关联至对应样本记录，状态设为 `pending_review`
3. 顾问审核通过后，将状态更新为 `published`
4. **审核红线**：报告禁止AI直接对客交付，必须经顾问人工审核

**输出物**：个人报告已关联样本，状态为 `published`（已发布）

---

### Step 3：群体报告生成（1-2 天）

**执行人**：测评顾问 + 数据分析师

#### 3.1 群体报告结构

```
群体测评分析报告

一、项目概览
   1.1 测评背景与目标
   1.2 样本概况（人数、部门、层级分布）
   1.3 参与率与数据质量

二、团队画像
   2.1 整体得分分布（各维度均值与标准差）
   2.2 与常模/标杆对比
   2.3 团队优势与短板

三、群体分析
   3.1 部门/层级差异分析
   3.2 性别/年龄差异分析（如适用）
   3.3 人群细分画像（聚类结果）

四、岗位匹配分析（如适用）
   4.1 各岗位匹配度分布
   4.2 高匹配/低匹配人群特征
   4.3 人岗配置建议

五、人才九宫格（如适用）
   5.1 绩效-潜力矩阵分布
   5.2 各象限人群特征
   5.3 发展建议（按象限）

六、风险预警
   6.1 团队风险指标
   6.2 需关注个体清单（匿名）
   6.3 干预建议

七、行动建议
   7.1 组织层面建议
   7.2 团队层面建议
   7.3 个人发展建议（群体共性）

八、附录
   8.1 测评工具说明
   8.2 统计方法说明
   8.3 数据质量报告
```

#### 3.2 可视化规范

| 图表类型 | 用途 | 工具 |
|----------|------|------|
| 雷达图 | 多维度对比 | ECharts / D3 |
| 柱状图 | 得分分布 | ECharts |
| 箱线图 | 群体差异 | ECharts |
| 散点图 | 九宫格矩阵 | ECharts |
| 热力图 | 相关性矩阵 | ECharts |
| 漏斗图 | 完成率/转化率 | ECharts |

**输出物**：群体报告（PDF/PPT/在线 Dashboard）

---

### Step 4：报告审核（0.5 天）

**执行人**：测评顾问主管 + PM

**审核清单**：

- [ ] 数据准确性：报告中的数字与原始数据一致
- [ ] 逻辑一致性：解读与数据匹配，无矛盾
- [ ] 专业合规：无医疗诊断表述，无歧视性语言
- [ ] 客户定制：符合客户要求的格式和内容
- [ ] 保密性：群体报告中个体信息已脱敏

**审核结果**：
- 通过：进入交付环节
- 修改：记录问题，返回修改
- 重大修改：需重新分析或调整模板

**输出物**：《报告审核记录》

---

### Step 4.5：生成B端门户访问Token

> 报告审核通过后，生成B端专属访问Token，通知B端通过门户查看和下载报告。

**执行人**：平台方（经营者）

#### 操作步骤

1. 在工作台「测评批次 → 门户访问」中点击「生成访问Token」
2. 配置Token有效期（默认30天，可调整）
3. 系统生成专属Token，门户入口：`/portal/batch/[token]`
4. 将门户链接通过邮件或微信发送给B端项目负责人

#### B端门户功能

通过该Token，B端可访问：

| 功能 | 说明 |
|------|------|
| 批次进度看板 | 样本完成率、各状态数量统计 |
| 个人报告下载 | 按样本ID下载对应PDF（仅已发布报告可见） |
| 群体报告下载 | 下载完整群体分析报告 |
| 结项报告下载 | 下载项目交付结项摘要 |

#### 注意事项

- Token有效期内B端可多次访问，到期后自动失效
- 如需提前撤销，在工作台手动设置 `is_active = false`
- **C端报告获取（可选）**：B端下载个人报告后，可自行通过ID↔真名映射转发给受测者；平台不直接接触C端，不存储受测者联系方式

**输出物**：B端门户Token已生成，访问链接已通知B端项目负责人

---

### Step 5：报告交付与解读（1-2 天）

**执行人**：PM + 测评顾问

#### 5.1 交付方式

| 方式 | 适用场景 | 操作要点 |
|------|----------|----------|
| **在线平台** | 客户有账号体系 | 上传至客户平台，通知查看 |
| **邮件发送** | 个人报告 | 加密 PDF 附件，设置查看密码 |
| **线下汇报** | 群体报告、高管汇报 | 准备 PPT，现场演示 |
| **混合交付** | 综合场景 | 在线 + 线下结合 |

#### 5.2 专家解读

**解读形式**：

| 形式 | 时长 | 参与人 | 内容 |
|------|------|--------|------|
| **一对一解读** | 30-60 min | 高管/关键人才 | 个人报告深度解读 |
| **团队解读** | 2-3 h | 团队 + 管理者 | 群体报告 + 互动讨论 |
| **管理层汇报** | 1-2 h | 高管 + HR | 战略层面洞察 + 建议 |

**解读要点**：
1. 先讲数据，再讲洞察，最后讲建议
2. 强调测评的参考价值，非唯一标准
3. 关注积极面，建设性提出改进点
4. 回答疑问，管理期望

#### 5.3 交付确认

- 客户签收《报告交付确认单》
- 确认报告数量、格式、内容无误
- 记录客户反馈和后续需求

**输出物**：《报告交付确认单》、解读会议纪要

## 4. 常见问题与应对

| 问题 | 应对策略 |
|------|----------|
| 客户对报告结果不认可 | 解释测评原理和局限性，提供常模参照，必要时安排复测 |
| 受测者要求删除数据 | 依据合同和法规处理，通常需客户 HR 同意 |
| 报告中的敏感信息泄露 | 立即启动应急预案，评估影响，通知相关方 |
| 客户要求额外分析 | 评估工作量，签订补充协议或作为增值服务 |
| 解读现场出现负面情绪 | 暂停解读，私下沟通，必要时转介专业心理咨询 |
