# 阶段1：需求确认与方案设计

> [← 返回全景SOP](../00-全景SOP.md)
>
> **阶段目标**：深入了解客户真实需求，设计匹配的心理测评解决方案
> **平均周期**：3-7 个工作日
> **责任主体**：项目经理 (PM) 主导，测评专家 (PO) 支持

---

## 1. 触发条件

- 阶段 0 评估结果为「绿灯」或「黄灯（风险已应对）」
- CRM 商机状态为「已立项」

---

## 2. 操作流程

### Step 1：需求调研（1-2 天）

**执行人**：PM + 测评顾问
**形式**：深度访谈 / 工作坊 / 问卷

#### 1.1 业务需求调研

**访谈对象**：HR 负责人、业务线负责人、高管（视项目规模）

**核心问题清单**：

| 维度 | 关键问题 | 目的 |
|------|----------|------|
| **组织背景** | 公司战略方向？当前面临的人才挑战？ | 理解测评的宏观价值 |
| **测评目标** | 要解决什么具体问题？期望达成什么效果？ | 明确成功标准 |
| **目标人群** | 具体岗位/层级？人数？地域分布？ | 确定测评规模和形式 |
| **应用场景** | 招聘？晋升？团队融合？培训前测？ | 选择合适工具和方法 |
| **对标要求** | 是否有行业标杆或内部标杆？ | 设计对比分析维度 |
| **结果使用** | 结果将如何使用？谁有权查看？ | 设计权限和报告层级 |

#### 1.2 技术需求调研

**访谈对象**：IT 负责人（如涉及系统对接）

- [ ] 是否需要与 HRIS/ATS/OA 系统对接？
- [ ] 单点登录 (SSO) 需求？
- [ ] 数据存储位置要求（本地/云端/混合）？
- [ ] 并发用户峰值预估？
- [ ] 移动端支持要求？

#### 1.3 合规需求调研

**访谈对象**：法务/合规负责人（如涉及敏感行业）

- [ ] 数据分类分级要求？
- [ ] 知情同意书模板是否需要定制？
- [ ] 数据保留期限要求？
- [ ] 审计和报告要求？

**输出物**：《需求调研记录》（含访谈纪要）

---

### Step 2：需求分析与文档化（1 天）

**执行人**：PM

**操作内容**：

1. **整理需求清单**：
   - 将调研信息分类为「必须 have」「应该 should」「可以 could」「不会 won't」
   - 使用 MoSCoW 方法优先级排序

2. **识别风险与假设**：
   - 记录所有假设条件（如：客户将提供完整的员工名单）
   - 标记风险项（如：客户内部决策链可能变化）

3. **编写《需求确认书》**：

```markdown

[简述客户背景、行业特点、项目缘起]

### 4.2 测评形式
□ 在线自评  □ 360度他评  □ 情境模拟  □ 结构化访谈

### 4.3 测评语言

## 五、交付物
```

### Step 3：测评方案设计（1-2 天）

**执行人**：测评顾问主导，PM 协调

#### 3.1 工具配置

**操作内容**：
1. 根据需求选择/配置测评工具：
   - 从题库中选择合适的量表
   - 配置逻辑跳转（如：根据岗位类型显示不同题目）
   - 设置时间限制和防作弊规则

2. 定制测评界面（如客户要求白标）：
   - 上传客户 LOGO
   - 配置品牌配色
   - 设置自定义欢迎语/结束语

#### 3.2 报告模板设计

**操作内容**：
1. 设计个人报告模板：
   - 报告结构：概览 → 详细维度 → 发展建议 → 行动计划
   - 可视化图表类型选择
   - 解读话术定制（匹配客户文化）

2. 设计群体报告模板：
   - 团队画像维度
   - 岗位匹配度分析
   - 人才九宫格分布
   - 风险预警指标

#### 3.3 技术方案（如涉及系统对接）

**执行人**：技术团队

- API 接口设计
- 数据同步机制
- 安全认证方案

**输出物**：《测评方案》（含工具配置说明、报告样例、技术方案）

---

### Step 4：方案评审与确认（1 天）

**执行人**：PM
**参与人**：客户（决策人）、BD、测评顾问

**会议议程**：
1. 需求回顾（5 min）
2. 方案展示（20 min）：
   - 测评工具介绍
   - 报告样例展示
   - 时间计划确认
3. 疑问解答（15 min）
4. 确认与签字（10 min）

**输出物**：
- 会议纪要
- 签字版《需求确认书》
- 签字版《测评方案》

---

## 3. 阶段出口检查清单

- [ ] 《需求确认书》已获客户签字
- [ ] 《测评方案》已获客户签字
- [ ] 测评工具已配置完成（测试环境）
- [ ] 报告模板已设计并展示样例
- [ ] 时间计划已确认
- [ ] 所有假设和风险已记录
- [ ] CRM 商机状态更新为「需求已确认」

---

## 4. 常见问题与应对

| 问题 | 应对策略 |
|------|----------|
| 客户对测评工具不信任 | 提供信效度数据、同行业案例、试测机会 |
| 客户要求修改已确认的需求 | 启动变更流程，评估影响，书面确认 |
| 技术方案客户 IT 不认可 | 安排技术对接会，提供标准接口文档 |
| 客户希望增加免费测试人数 | 明确免费额度，超出部分按标准报价 |
| 报告模板客户不满意 | 提供 2-3 个风格选项，或按客户 VI 定制 |
