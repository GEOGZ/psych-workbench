# 阶段3：项目执行与交付监控

> [← 返回全景SOP](../00-全景SOP.md)
>
> **阶段目标**：按计划执行测评项目，实时监控进度与质量，确保按时交付
> **平均周期**：按项目规模（通常 2-8 周）
> **责任主体**：项目经理 (PM) 主导，技术团队支持，测评顾问执行

---

## 1. 触发条件

- 阶段 2 完成，合同已签署，预付款到账
- CRM 商机状态为「合同已签署」

---

## 2. 操作流程

### Step 1：项目启动会（0.5 天）

**执行人**：PM
**参与人**：客户（HR 负责人、IT 对接人）、我方（PM、测评顾问、技术支持）

#### 1.1 会议议程

| 时间 | 议题 | 负责人 |
|------|------|--------|
| 10 min | 项目背景与目标回顾 | PM |
| 15 min | 测评方案确认 | 测评顾问 |
| 10 min | 系统配置与对接说明 | 技术支持 |
| 10 min | 时间计划与里程碑 | PM |
| 10 min | 双方职责与对接机制 | PM |
| 5 min | 答疑与确认 | 全体 |

#### 1.2 启动会输出

- [ ] 《项目启动会议纪要》
- [ ] 双方确认的项目时间计划（甘特图）
- [ ] 沟通机制（微信群/邮件组/周会时间）
- [ ] 客户方对接人清单

**输出物**：《项目启动会议纪要》、更新版《项目计划》

---

### Step 2：系统配置与测试（1-3 天）

**执行人**：技术团队 + 测评顾问

#### 2.1 环境配置

**操作清单**：

| 配置项 | 操作内容 | 验收标准 |
|--------|----------|----------|
| **测评环境** | 创建项目空间，配置测评工具 | 可正常访问，无报错 |
| **白标定制** | 上传 LOGO、配色、域名绑定 | 视觉与客户品牌一致 |
| **用户导入** | 导入受测者名单（姓名、邮箱、部门） | 数据准确，格式正确 |
| **权限配置** | 配置客户管理员账号、PM 账号 | 权限边界清晰 |
| **邮件模板** | 配置邀请邮件、提醒邮件、完成通知 | 内容准确，发送正常 |

#### 2.2 测试验证

**测试场景**：

1. **功能测试**：
   - [ ] 受测者注册/登录流程
   - [ ] 测评题目正常显示、跳转正确
   - [ ] 计时功能正常
   - [ ] 防作弊规则生效

2. **兼容性测试**：
   - [ ] Chrome / Edge / Safari / Firefox
   - [ ] PC / 平板 / 手机
   - [ ] 不同分辨率

3. **性能测试**：
   - [ ] 目标并发数下响应时间 < 3s
   - [ ] 同时在线人数无卡顿

4. **报告测试**：
   - [ ] 个人报告生成正确
   - [ ] 数据可视化正常
   - [ ] PDF 导出格式正确

**输出物**：《系统配置完成确认单》、《测试报告》

---

### Step 3：受测者邀请与执行（按项目规模）

**执行人**：PM + 客户 HR

#### 3.1 邀请发送

**操作内容**：
1. 批量发送测评邀请邮件/短信
2. 邮件内容包含：
   - 测评目的说明
   - 操作指引（含链接）
   - 截止时间
   - 技术支持联系方式

3. 邀请模板：

```
主题：[客户公司名] 人才发展测评邀请

尊敬的 [姓名]：

您好！您被邀请参加 [客户公司名] 组织的人才发展测评。

【测评目的】
本次测评旨在了解您的 [领导力/性格特质/认知能力等]，为您的人才发展提供科学参考。

【操作指引】
1. 点击链接：[测评链接]
2. 使用您的邮箱登录
3. 按指引完成测评（预计耗时 [XX] 分钟）
4. 请在 [截止日期] 前完成

【注意事项】
- 请选择安静、不受打扰的环境
- 请如实作答，无对错之分
- 测评过程中请勿刷新页面或后退

【技术支持】
如遇问题，请联系：[PM 姓名] [电话] [邮箱]

感谢您的参与！
```

#### 3.2 进度监控

**监控指标**：

| 指标 | 计算方式 | 健康阈值 |
|------|----------|----------|
| **邀请送达率** | 成功送达 / 总邀请数 | ≥ 95% |
| **登录率** | 已登录 / 总邀请数 | ≥ 80% |
| **完成率** | 已完成 / 总邀请数 | ≥ 75% |
| **平均完成时间** | 总耗时 / 完成人数 | 在预期范围内 |
| **异常提交数** | 触发防作弊规则数 | < 5% |

**监控频率**：
- 每日 10:00 查看前一日数据
- 完成率 < 50% 时，每日同步客户
- 完成率 ≥ 80% 时，每 2 日同步

#### 3.3 催办机制

| 触发条件 | 动作 | 执行人 |
|----------|------|--------|
| 邀请后 48h 未登录 | 发送提醒邮件 | 系统自动 |
| 截止前 3 天未完成 | 发送催办公告 | PM + 客户 HR |
| 截止前 1 天未完成 | 电话/微信单独提醒 | 客户 HR |
| 截止日未完成 | 确认是否延期或放弃 | PM 与客户协商 |

**输出物**：每日《进度监控报告》、催办记录

---

### Step 4：数据质量检查（测评结束后 1 天）

**执行人**：测评顾问 + 数据分析师

#### 4.1 数据完整性检查

- [ ] 实际完成人数 vs 计划人数
- [ ] 缺失数据比例（题目漏答率）
- [ ] 无效问卷识别（作答时间过短、规律性作答等）

#### 4.2 数据有效性检查

| 检查项 | 方法 | 处理标准 |
|--------|------|----------|
| **作答时间** | 统计每份问卷用时 | 低于最短合理时间 → 标记无效 |
| **一致性检验** | 前后相似题目答案一致性 | 矛盾率 > 30% → 标记无效 |
| **极端作答** | 全部选同一选项 | 标记无效 |
| **开放题质量** | 内容相关性、认真程度 | 明显敷衍 → 标记无效 |

#### 4.3 无效数据处理

- 无效问卷比例 < 10%：直接剔除，不影响分析
- 无效问卷比例 10-20%：补充邀请或调整样本
- 无效问卷比例 > 20%：分析原因，可能需要重新测评

**输出物**：《数据质量检查报告》、清洗后数据集

---

### Step 5：里程碑验收（按项目计划）

**执行人**：PM
**参与人**：客户（HR 负责人）

#### 5.1 里程碑定义

| 里程碑 | 验收内容 | 验收标准 |
|--------|----------|----------|
| M1：系统上线 | 测评平台配置完成 | 客户确认可正常使用 |
| M2：邀请完成 | 所有受测者已邀请 | 邀请送达率 ≥ 95% |
| M3：测评完成 | 数据收集结束 | 完成率达标，数据质量合格 |
| M4：报告交付 | 个人/群体报告已生成 | 客户确认报告质量 |
| M5：汇报解读 | 专家解读已完成 | 客户确认解读价值 |

#### 5.2 验收流程

1. PM 提交《里程碑验收申请》
2. 客户 3 个工作日内确认或提出修改意见
3. 验收通过：双方签字确认
4. 验收不通过：记录问题，制定整改计划

**输出物**：《里程碑验收单》（双方签字）

---

## 3. 阶段出口检查清单

- [ ] 所有里程碑验收通过
- [ ] 数据质量合格（有效数据率 ≥ 85%）
- [ ] 客户对执行过程满意度 ≥ 4/5
- [ ] 所有过程文档归档
- [ ] CRM 商机状态更新为「执行完成」

---

## 4. 常见问题与应对

| 问题 | 应对策略 |
|------|----------|
| 完成率低于预期 | 分析原因（邀请未达、时间冲突、技术问题），针对性催办 |
| 客户临时增加人数 | 评估影响，签订补充协议，调整时间计划 |
| 系统出现技术故障 | 立即启动应急预案，通知客户，技术团队紧急修复 |
| 受测者投诉题目不适 | 记录投诉内容，评估是否调整，必要时提供心理支持资源 |
| 客户要求提前看数据 | 明确约定数据在报告交付前不单独提供，避免误解 |
