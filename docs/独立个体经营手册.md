## 一、为什么需要这本手册

传统咨询/测评公司的 SOP 默认有 6 类角色协作:BD、PM、测评顾问、法务、技术、CSM,外加 QA、财务、总监做审批。

**独立个体只有一个人**,但客户期待的专业度不能因此降级。
本手册的作用是回答三个问题:

1. **一个人怎么扮演 6 个角色** —— 「四顶帽子」模型
2. **没有审批人时怎么保证质量与合规** —— 「自检清单 + 阈值规则 + 复盘记录」三件套
3. **一个人能接多少活、按什么节奏收钱才能不死** —— 容量上限 + 现金流模型

如果一份 SOP 写了「商务总监审批」、「PM 主管升级」、「QA 30% 抽检」,那它不是给你写的——
它是给一家 30 人公司写的。**本手册负责把那些约定翻译成你一个人能执行的版本。**

## 二、四顶帽子模型(Four Hats)

### 2.1 帽子定义

| 帽子 | 角色对应(传统团队) | 核心产出 | 时间占比目标 |
|------|---------------------|----------|--------------|
| 🎩 **销售帽** | BD + 商务 + CSM(获客侧) | 线索、商机、合同、续约 | 25% |
| 🧠 **顾问帽** | 测评顾问 + 心理学专家 | 方案、报告解读、危机干预判断 | 30% |
| 🛠 **交付帽** | PM + 技术 + 数据分析师 | 平台配置、数据采集、报告生成、客户沟通 | 30% |
| 📊 **经营帽** | 老板 + 财务 + 法务 + PMO | 收款、合规、复盘、定价、产品迭代 | 15% |

合计 100%。**核心约束:同一时段只戴一顶帽子。** 切帽子有切换成本,要在日程上显式划分。

### 2.2 帽子日程(参考模板)

```
周一  上午 销售帽    │ 下午 经营帽
周二  上午 顾问帽    │ 下午 交付帽
周三  全天 交付帽(深度工作日,关闭即时通讯)
周四  上午 顾问帽    │ 下午 销售帽
周五  上午 交付帽    │ 下午 经营帽(本周复盘 + 下周计划)
周末  默认不戴帽子;紧急情况只处理 P0 异常
```

**例外规则**:
- 客户启动会、解读会按客户日历,不受帽子日程约束
- 项目数据上线/上线后第一天的监控,优先级覆盖帽子日程
- 同一天如果跨 ≥3 顶帽子,第二天必须有半天「无帽子缓冲」

### 2.3 「这件事谁干」决策表

旧 SOP 里所有 RACI 行,统一映射如下:

| 旧 SOP 描述 | 在本手册下 |
|--------------|-----------|
| BD/商务负责 | 戴 🎩 销售帽 |
| PM 负责 | 戴 🛠 交付帽 |
| 测评顾问负责 | 戴 🧠 顾问帽 |
| 法务/财务负责 | 戴 📊 经营帽(或外包,见 §四) |
| 技术团队负责 | 戴 🛠 交付帽(或外包,见 §四) |
| QA 抽检 | 戴 📊 经营帽自查 + 工具自动校验 |
| 总监/总经理审批 | 阈值规则(见 §三) |
| CSM 跟进 | 戴 🎩 销售帽(续约侧)+ 🛠 交付帽(交付侧) |

## 三、自检清单 + 阈值规则 + 复盘日志(替代审批)

### 3.1 为什么不能有审批

独立个体没有「上级」。把「审批」写进 SOP 等于给自己挖一个永远填不平的坑——
你最终会要么跳过它(SOP 失效),要么被它拖死(没人能签字)。

正确做法是**事前阈值 + 事中自检 + 事后复盘**:

```
旧:  PM 提交 → 主管审核 → 总监审批 → 执行
新:  阈值检查(自动判定) → 自检清单(手动签到) → 执行 → 复盘记录(每月汇总)
```

### 3.2 阈值规则总表

任何超过阈值的决策**强制 24 小时冷静期**(自己跟自己谈判),并写入复盘日志:

| 决策类型 | 阈值 | 触发后动作 |
|----------|------|-----------|
| **报价折扣** | ≤ 标准价 85% | 直接执行 |
| | 标准价 70%–85% | 24h 冷静期 + 复盘记录(为什么打折) |
| | < 标准价 70% | 拒绝或拆小试单(见 §六现金流) |
| **合同金额** | ≤ 5 万 | 模板合同直接签 |
| | 5–20 万 | 模板合同 + 自检清单(见 §3.3) |
| | > 20 万 | 必须经一次性外部律师审(见 §四外包池) |
| **项目周期** | ≤ 4 周 | 直接接 |
| | 4–8 周 | 接,但确认与现有项目无时间冲突 |
| | > 8 周 | 拆分为多个里程碑合同 |
| **单客户额度** | < 年度营收 30% | 直接接 |
| | 年度营收 30%–50% | 接,但启动客户多元化预警 |
| | > 50% | 不接,或要求 60%+预付款 |
| **范围变更** | 工作量增加 < 10% | 直接做,口头确认 |
| | 10–30% | 书面变更单 + 不加价但延期 |
| | > 30% | 书面变更单 + 加价 + 延期 |
| **危机事件** | 受测者表达自伤/自杀意念 | **立刻**戴顾问帽,启动危机干预协议(见 §五) |

### 3.3 关键自检清单(必须打勾才能进入下一步)

**📋 合同自检清单(签合同前)**
- [ ] 付款条件包含 50%/30%/20% 或等价分期
- [ ] 写明「测评工具来源与授权」(自研/采购授权/开源)
- [ ] 写明「常模来源」与「报告解释边界」(非临床诊断)
- [ ] 写明「数据保留期与销毁时点」
- [ ] 写明「危机干预转介义务」(我转介给客户 EAP/属地热线,不承担临床责任)
- [ ] 写明「单方退出/暂停条款」(防止客户拖款)
- [ ] 案例使用授权(可选,默认不授权)
- [ ] 我自己读完一遍,没有看不懂的条款

**📋 报告交付自检清单(交付前)**
- [ ] 数据样本量 ≥ 工具最低要求
- [ ] 个人报告:每个受测者都有,不缺漏
- [ ] 群体报告:数据口径与原始数据可追溯(留 SQL/脚本)
- [ ] 没有把测评结果写成临床诊断词汇(如「抑郁症」「焦虑障碍」)
- [ ] 高风险个体已识别,转介建议已写明
- [ ] PDF 渲染无乱码、无错别字(本机预览 + 手机预览各一次)
- [ ] 客户敏感信息(姓名/工号)展示符合合同约定的脱敏粒度

**📋 上线自检清单(开放测评链接前)**
- [ ] 测试链接自己完整跑一遍(从邀请邮件到提交)
- [ ] 数据落库有,且字段完整
- [ ] 链接过期时间设置正确
- [ ] 客户白标 logo/文案确认无误
- [ ] 受测者 FAQ 已备齐(常见问题 ≥ 5 个)
- [ ] 危机干预联系方式在测评首页可见

### 3.4 复盘日志(月度)

每月 1 日(或最近的工作日)戴 📊 经营帽,30 分钟,回答 5 个问题:

1. 上月触发了哪些阈值?触发后我做了什么?事后看决策对不对?
2. 上月有哪些自检清单**没打勾就过去了**?为什么?
3. 上月有哪些异常事件?分类是 P0/P1/P2/P3?
4. 上月 4 顶帽子时间占比是否符合 25/30/30/15?偏差最大的是哪顶?
5. 下月需要调整的 1 件事是什么?

**记录在哪里**:`docs/复盘日志/YYYY-MM.md`(单文件,Markdown,不超过 1 屏)。

## 四、AI 替代矩阵 + 外包池

### 4.1 设计原则

- **AI 替代**:重复性、模板化、低风险的工作 → 用 LLM/脚本/SaaS 工具
- **外包**:一次性、专业资质、高风险的工作 → 找专业人员按次付费
- **自己做**:涉及客户关系、专业判断、品牌信任的工作

### 4.2 AI 替代矩阵

| 阶段 | 工作项 | AI 替代方式 | 残留人工部分 |
|------|--------|-------------|---------------|
| 准入 | 客户背调 | LLM 检索 + 行业新闻 + 工商信息汇总 | 我判断行业敏感度 |
| 需求 | 访谈提纲 | LLM 基于行业模板生成 | 现场访谈、追问 |
| 需求 | 会议纪要 | 录音 → 转写(Whisper)→ LLM 摘要 | 我审一遍发出 |
| 商务 | 合同起草 | 模板填充(变量替换) | 阈值 > 20 万走外部律师 |
| 商务 | 报价单 | 标准价目表 + 折扣阈值规则 | 我做让步谈判 |
| 执行 | 受测者邀请邮件 | 模板 + 邮件合并 | 我审样本 |
| 执行 | 进度提醒 | 自动化(Cron + 邮件/短信) | 我处理异常 |
| 报告 | 个人报告生成 | 模板 + LLM 填充段落 + 规则引擎 | **我必须复核每一份**(初期 100%,稳定后高风险样本 100% + 其余抽检 20%) |
| 报告 | 群体报告统计 | Python/SQL 脚本 + 可视化模板 | 我写洞察与建议 |
| 报告 | 报告解读会 PPT | LLM 基于报告自动生成大纲 | 我做现场讲解 |
| 收尾 | NPS 问卷发送 | 自动化触发 | 我看结果 |
| 收尾 | 结项报告 | 模板 + 项目数据自动填充 | 我写总结与建议 |
| 经营 | 应收账款提醒 | 自动化 Cron | 我打催款电话 |
| 经营 | 月度复盘数据汇总 | 工作台后端聚合 | 我写复盘 |

**红线**:以下事项**禁止 AI 直接对客**(必须人工复核才能发出):
- 任何写有受测者姓名的报告内容
- 任何回复客户高管的邮件/消息
- 任何涉及合同金额的对外沟通
- 任何危机干预相关沟通

### 4.3 外包池(按需付费)

| 角色 | 触发条件 | 预期成本 | 寻源建议 |
|------|----------|----------|---------|
| **执业律师** | 合同金额 > 20 万 / 客户提出非标条款 / 涉及跨境数据 | 单次审 ¥2k–5k;模板审定一次 ¥8k–15k | 先做一次模板审定,后续复用 |
| **持证心理咨询师** | 受测者出现高危信号需要专业转介 / 客户要求面对面解读 ≥ 50 人 | 解读 ¥1.5k–3k/场;危机咨询按小时 | 与 1–2 位建立长期合作关系 |
| **平面/PPT 设计师** | 群体报告对外汇报 / 客户案例对外发布 | ¥500–2k/份 | 设计平台 + 1 位长期合作 |
| **前端外包** | 工作台超出我能维护的复杂度 | 按周计费 | 仅在 MVP 跑通且现金流允许后启用 |
| **会计/记账** | 月营收 > ¥5 万 / 需要开专票 | ¥300–800/月 | 本地代理记账公司 |
| **测评工具采购** | 自研工具不覆盖客户需求(如 Hogan、SHL) | 按人次/按年授权 | 与厂商谈年框 |

**外包的三条铁律**:
1. **不外包客户关系**:沟通永远是我直接对客户
2. **不外包核心 IP**:报告解释逻辑、模板、知识沉淀必须在我手上
3. **签 NDA**:所有外包都签保密协议,涉及客户数据的全部脱敏

## 五、危机干预与伦理底线

### 5.1 我的角色边界

**我做的**:组织发展类、人才发展类、团队画像类心理测评;基于常模的个体差异分析与建议
**我不做**:临床心理诊断、心理治疗、危机咨询的持续介入、司法鉴定

每份合同、每份报告、每个测评首页都必须重申这条边界。

### 5.2 高风险信号识别

测评数据/沟通中出现以下任一情况,立刻戴顾问帽:

- 自评量表中自伤/自杀相关题项分数显著偏高(具体阈值由所用工具定义)
- 受测者在自由作答/沟通中表达自伤、自杀、伤害他人意念
- 客户 HR 主动告知某受测者近期有重大变故
- 群体数据中某团队多项消极指标极端值聚集

### 5.3 危机干预协议(SOP)

```
发现高风险信号
    ↓
1. 24h 内联系客户对接人(HR/EAP),书面通报(留痕)
    ↓
2. 提供属地心理援助热线 + 客户 EAP 联系方式
    ↓
3. 在个人报告中明确建议「专业转介」(不写诊断词)
    ↓
4. 如客户无 EAP 且为非小型客户,要求合同补充协议指定专业资源
    ↓
5. 复盘日志记录(P1 事件)
```

**不做的事**:
- 不直接联系受测者本人提供持续咨询
- 不在报告中使用诊断性词汇(抑郁症/焦虑障碍/人格障碍)
- 不向客户透露超出合同约定的个体信息

### 5.4 合同模板必须包含的伦理条款

- 测评目的限定(组织发展/人才选拔/团队建设之一)
- 数据使用范围(不得用于绩效处分/解雇唯一依据)
- 受测者知情同意(客户负责取得)
- 危机干预转介义务(我转介,客户跟进)
- 数据保留期(默认项目结项后 12 个月)与销毁方式

## 六、容量上限 + 现金流模型

### 6.1 容量上限(硬约束)

| 维度 | 上限 | 依据 |
|------|------|------|
| 同时进行中(执行+报告阶段)的项目数 | **≤ 3** | 单人能保证质量的并行上限 |
| 年度交付项目总数 | **12–15** | 按平均交付周期 4–6 周倒推 |
| 单项目周期 | ≤ 8 周 | 超过则拆分里程碑合同 |
| 单客户年度占比 | ≤ 50% 营收 | 防止单客户依赖 |
| 顾问帽周时长 | 12–18 小时 | 保证专业判断质量 |

**到达上限怎么办**:
- 优先级排序:已签合同 > 高分准入客户 > 续约 > 新询单
- 新询单超过容量 → 礼貌延期 / 推荐合作伙伴 / 拆小试单
- 不要承诺自己做不到的交付期

### 6.2 现金流分期模型(标准条款)

```
合同签署后 7 日内    : 50% 预付款(项目启动金,不到账不开测评)
测评数据收集完成     : 30% 中期款(报告制作启动金)
报告交付 + NPS 完成  : 20% 尾款(30 日内付清)
```

**单客户敞口规则**:

| 应收账款占比 | 状态 | 行动 |
|--------------|------|------|
| 应收 ≤ 月度成本 × 1 | 健康 | 正常推进 |
| 应收 > 月度成本 × 2 | 预警 | 戴销售帽 + 经营帽,逐项催收 |
| 应收 > 月度成本 × 3 | 红线 | **暂停**该客户新工作,集中催收 |
| 单客户应收 > ¥10 万 且 > 30 天 | 红线 | 律师函成本评估,准备启动 |

### 6.3 应急资金缓冲

- 个人/经营账户保留 ≥ 3 个月固定支出的现金缓冲
- 不依赖单一客户尾款支付下月开支
- 大额支出(工具年费、设计/律师费)集中在收到尾款后的当月

### 6.4 定价底线

| 项目类型 | 最低定价(锚点) | 不接的信号 |
|----------|----------------|------------|
| 个人测评(标准化报告) | ¥800–2000/人(随量阶梯下降) | 单价 < ¥500 直接拒 |
| 群体报告(20–50 人) | ¥3–8 万/项目 | < ¥3 万 拒 |
| 群体报告(50–200 人) | ¥8–20 万/项目 | < ¥8 万 拒 |
| 解读会(线下) | ¥3k–8k/场 | < ¥3k 拒 |
| 长期顾问(年框) | ¥10 万+/年 | 现阶段不接(超容量) |

## 七、SLA(基于工作时区的现实承诺)

### 7.1 真实 SLA(写进合同)

| 客户期待 | 我的承诺 | 解释 |
|----------|----------|------|
| 即时回复 | **工作日 9:00–18:00 内 4 小时回复** | 写入合同的 SLA |
| 周末/夜间 | **次个工作日上午 12:00 前回复** | 受测者紧急情况除外 |
| 报告交付 | **数据收集完成后 7 个工作日** | 不算受测者补测延误 |
| 异常处理 | P0 即时 / P1 24h / P2 3 工作日 / P3 月度复盘 | 见 §三阈值规则 + 异常处理手册 v1.1 |

### 7.2 期望管理(在启动会必讲)

启动会议程必含以下三句话:

1. 「我是这个项目的唯一对接人,所有事项请直接联系我;我会在工作时间 4 小时内回复。」
2. 「项目里所有里程碑都在工作台可见,请优先在工作台沟通,留痕便于追溯。」
3. 「如果出现自伤/自杀类信号,我会在 24 小时内书面通报 HR;请提前告诉我贵司 EAP 联系方式。」

## 八、工作台对本手册的支撑(给开发用)

工作台 MVP 必须直接支持本手册的下列机制(否则手册无法落地):

| 机制 | 工作台支持点 | 优先级 |
|------|-------------|--------|

## 九、什么时候这本手册「过期」

如果有一天:

- 同时进行项目 > 3 持续超过 2 个月,且收入足够支付一名全职助理
- 报告生成的人工复核成为最大瓶颈
- 法务/财务外包月度费用 > 招一个兼职的成本

那就**不再是独立个体阶段了**。本手册转为「创业期」手册,需要重写为团队 SOP。

**触发任一条件,开启 90 天扩张评估期**:
1. 评估固定成本上升幅度
2. 评估能否找到价值观一致的合伙人/雇员
3. 评估扩张后单项目利润率是否依然健康
4. 决定:维持独立个体(主动拒单) / 招一人 / 转为团队公司
